# LocalGPT 0.2.0

[English release notes](https://github.com/ThineLord/localgpt/blob/v0.2.0/docs/releases/0.2.0.md) · [更新历史](https://github.com/ThineLord/localgpt/blob/v0.2.0/CHANGELOG.md)

发布日期：2026-11-09。本版是运行时源码更新，不会自动部署到已有安装，也不包含模型。

## 更新内容

- **安全恢复中断对话。** 升级后的 UI 和 ComfyUI 写入端共享 POSIX 所有权锁。已确认失去所有者的 chat/routing 任务保留部分回答和请求身份，结束旧尝试并解除新对话阻塞；重试必须由用户发起，不自动重放模型调用；HTTP 异步清理结束后才发布完成状态，避免紧接着发送时与旧所有者竞争。活跃任务、图像任务和旧版所有权未知任务不会被盲目清空。
- **无模型演示可完整运行。** 图像改为带明确模拟标识的 PNG，使用生产预览和下载路由；SVG 仍被拒绝。演示图像不代表模型推理结果。
- **项目检索不再占用主事件循环。** 导入时建立 SQLite 派生分块/词项索引，旧来源首次使用时后台补建。检索移入工作线程，保持原始来源、项目隔离、软删除/恢复、预算和停止行为。
- **看得见正在运行的版本。** “关于”显示界面和服务的版本/提交，注明本地修改和构建不一致。health 返回进程启动时身份；无 Git 的归档如实显示提交未知。
- **本地诊断分别检查服务。** 刷新会独立检查应用数据库、LM Studio 和 ComfyUI。模型探测仅使用回环地址 GET、两秒超时、不跟随重定向、不公开响应内容、不启动服务或提交生成。“可连接”不等于推理已验收。
- **键盘焦点正确返回。** 桌面和手机布局关闭记忆窗口后，焦点回到设置中的触发按钮。
- **一键执行当前验收。** `.venv/bin/python tools/validate.py --setup` 安装固定依赖并运行完整合成套件，后续省略 `--setup`。报告区分完整、局部、阻塞、失败和中断；旧 Round 脚本保留在历史目录，并说明当前覆盖映射。

## 验证范围与局限

当前套件覆盖后端、任务所有权/恢复、工具及测试运行器负向控制、构建/版本/源码检查、检索性能和 15 个隔离浏览器/API 套件。浏览器实际操作停止/重试、PNG 预览下载、记忆、图库和媒体生命周期、项目来源及发送给模拟模型的上下文、中英文、响应式布局、版本和诊断。截图与录屏为本地合成证据，不发布个人数据。

100×200,000 字符基准使用重复合成文本。主验收预热查询约 0.07 秒，事件循环延迟约 1–2 毫秒；独立审查并行负载下约 0.24 秒、141 毫秒。旧索引首次补建另有开销。这些结果不保证所有文档或机器具有相同延迟；明确回归门槛为预热查询一秒、事件循环延迟 250 毫秒。

真实 LM Studio 文本和 ComfyUI 图像推理仍需已安装、运行的本地服务及模型验收。合成通过不验证模型质量、GPU 内存行为、所有外部插件版本、断电恢复、网络/共享文件系统或原生 Windows。没有启用付费 CI；本地通过不能代替仓库要求的远端检查。

本次发布验收重查 LM Studio（1234）和 ComfyUI（8188）均为 connection refused，因此真实文本/图像推理属于环境阻塞，不能算通过。没有修改生产安装。

## 升级与回退

1. 阅读[恢复协议](https://github.com/ThineLord/localgpt/blob/v0.2.0/docs/APP03_RECOVERY.md)，使用干净的 `v0.2.0` checkout，保留本地修改。
2. 安排协调维护：停止两个旧写入端，确认文本/图像任务空闲，备份包含已提交 WAL 的一致 SQLite 状态以及媒体和配置。不要替换活跃数据库或复制/删除正在使用的生成锁。
3. 同时升级独立 UI 源码与 ComfyUI 扩展。扩展将 `backend.py` 安装为 `__init__.py`，同时包含 `storage.py`、`generation.py`、`lm_chat.py`、`generation_ownership.py`、`build_info.py`、`diagnostics.py` 和重新构建的 `index.html`。启动前从目标提交构建，“关于”中的两个身份应一致。
4. 启动会增添所有权表，项目索引为可重建派生数据，按需补建。未知旧活跃任务仍需专门审查维护，不要删行或启用批量启动重置。
5. 在实际安装中验收 health、历史、停止/重试、本地服务和真实推理后，再恢复日常使用。更新 GitHub 不会自动完成上述部署步骤。

不要将单个写入端回退至 v0.1.0 并与新版混用。回退需停止两端，核对升级后的全部用户活动，仅在明确维护时恢复一致的旧环境，不能用旧备份覆盖新数据。发布标签不重写，后续修正使用新版本。
