# LocalGPT 0.2.0

[中文发布说明](https://github.com/ThineLord/localgpt/blob/v0.2.0/docs/releases/0.2.0.zh-CN.md) · [Changelog](https://github.com/ThineLord/localgpt/blob/v0.2.0/CHANGELOG.md)

Released 2026-11-09. This is a runtime source release; it does not deploy to an existing installation or bundle models.

## What changed

- **Interrupted chats recover safely.** Upgraded UI and ComfyUI writers share a POSIX ownership lock. Recognized abandoned chat/routing jobs retain partial answers and request identity, become recoverable terminal attempts, and no longer block a new chat. Retry is explicit; no model call is replayed. Completion is published only after asynchronous HTTP cleanup, so an immediate next request does not race the old owner. Active owners, image jobs and unknown legacy ownership are not blindly cleared.
- **The model-free demo works end to end.** Generated images are labeled synthetic PNGs. Preview and download use production routes; SVG remains rejected. No model inference is implied.
- **Project retrieval stays responsive.** SQLite stores derived chunks/terms at source import and backfills old sources on first use. Retrieval runs in a worker thread. Source content, isolation, soft-delete/restore, budgets and Stop remain respected.
- **You can identify what is running.** About shows interface and server version/commit, marks modified checkouts, and highlights mismatched builds. Health reports the process-start identity. Archives without Git report an unknown commit.
- **Local diagnostics are independent.** Refresh probes the application database, LM Studio and ComfyUI separately. Model probes are loopback-only GET requests with a two-second timeout, no redirects, no response-body disclosure and no generation/startup actions. Reachability does not establish inference readiness.
- **Keyboard focus returns correctly.** Closing Memory returns focus to its settings trigger on desktop and mobile.
- **Acceptance has one current entry.** `.venv/bin/python tools/validate.py --setup` installs locked dependencies and runs current synthetic acceptance. Subsequent runs omit `--setup`. The report distinguishes full, partial, blocked, failed and interrupted runs. Historical scripts remain documented separately.

## Validation and limits

The current suite covers backend/ownership/recovery, tools and runner negative controls, build/release/source checks, retrieval performance and 15 isolated browser/API contracts. The browser flows exercise chat Stop/Retry, PNG preview/download, memory, gallery and media lifecycle, projects and actual context composition into a synthetic model request, language, responsive layout, versions and diagnostics. Screenshots and recordings are local synthetic evidence, not published personal data.

The 100 × 200,000-character benchmark uses repeated synthetic text. Primary warm retrieval measured about 0.07 seconds with approximately 1–2 ms loop delay; independent review under concurrent load measured about 0.24 seconds and 141 ms. Cold rebuild adds first-use work. These are fixture measurements, not latency promises for all corpora or machines. The benchmark's explicit regression guards are one second warm retrieval and 250 ms event-loop delay.

Real LM Studio text inference and ComfyUI image inference require separately installed, running services and model acceptance. Synthetic passes do not validate model quality, GPU memory behavior, every external plugin version, physical power-loss recovery, shared/network filesystems or native Windows. Local validation does not substitute for a required remote check; no paid CI is enabled by this release.

At release acceptance, both LM Studio (1234) and ComfyUI (8188) returned connection refused. Real text/image inference was therefore environment-blocked, not passed. No production installation was modified.

## Upgrade and rollback

1. Read [the recovery protocol](https://github.com/ThineLord/localgpt/blob/v0.2.0/docs/APP03_RECOVERY.md). Use a clean checkout at `v0.2.0`; preserve any local modifications.
2. Schedule coordinated maintenance: stop both old writers, ensure text/image work is quiescent, and take a consistent SQLite backup that includes committed WAL state plus local media/configuration. Do not replace a live database or copy/delete its generation lock.
3. Upgrade the standalone source and installed ComfyUI extension together. The extension uses `backend.py` as `__init__.py`, plus `storage.py`, `generation.py`, `lm_chat.py`, `generation_ownership.py`, `build_info.py`, `diagnostics.py` and rebuilt `index.html`. Build from the intended commit before starting services; both identities should agree in About.
4. Startup adds ownership tables; project source indexes are derived and backfilled lazily. Unknown legacy active rows remain blocked for deliberate, reviewed maintenance. Do not delete them or enable a blanket startup reset.
5. Validate health, history, Stop/Retry, local services and real inference in the installation before resuming normal work. Updating GitHub alone does not perform these steps.

Do not roll only one writer back to v0.1.0 alongside upgraded writers. To roll back, stop both writers and account for all user activity since upgrade; restore a consistent pre-upgrade environment only under deliberate maintenance. Do not overwrite newer user data with an old backup. Release tags are immutable; corrections use a new version.
